# 插件真机验证探针（probes）

> 目的：把插件系统里**只能用真机确认**的几件事，从"待验证"变成"已验证"。
> 起因：1.1.28/1.1.29 的沙箱与执行上限只有源码/字节码层面的静态验证，
> 审计日志里没有任何 `call` 记录 —— 即插件的实际动作路径从未真正跑过。

## 前提

- App 版本 **1.1.30 或更高**
- 桌宠服务正在运行（设置页的按钮显示「停止桌宠」即表示在跑）
- 日志文件：`Download/whale-plugins.log.txt`（MediaStore 给 text/plain 补了 `.txt`）

安装方式：设置页 → **插件** → **安装** → 把下面某个 JSON 文件内容整段粘贴 → 确定。
安装后会弹出能力授权框。

---

## 探针 1：沙箱边界（`probe-sandbox.json`）

**授权**：勾选「让鲸鱼娘说话」（say）

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| `typeof Packages` | `undefined`（已删除该全局） |
| `typeof java` | `undefined` |
| `__bridge.getClass()` | 抛异常 → 记录 `getClass:blocked` |
| `__bridge.getClass().getClassLoader()` | 抛异常 → 记录 `getClassLoader:blocked` |
| 桌宠表现 | 正常冒一句「沙箱探针已执行，请看审计日志」 |

**判定**：审计日志出现 `probe-sandbox 结果: ... | getClass:blocked | getClassLoader:blocked`
→ 若出现 `getClass=class ...` 或 `getClassLoader=...`（非 blocked），**沙箱无效，必须立即反馈**。

## 探针 2：死循环保护（`probe-loop.json`）

**授权**：勾选 say

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| 审计日志 | 出现 `probe-loop 开始（预期被指令上限中止）` |
| 审计日志 | **不出现** `probe-loop 结束（这一行不应出现）` |
| 随后 | 出现一条 `事件处理 | error`（即超时被中止） |
| 桌宠表现 | 双击后鲸鱼娘**仍能正常游动/说话**，UI 不卡 |

**判定**：只要"结束"那行没出现、且桌宠没卡死 → 死循环保护有效。
若桌宠明显卡顿（几秒内无响应）→ 指令上限值（500 万）可能偏大，需下调。

> 注意：这一步会占用插件线程若干秒，属正常现象；期间**其它插件不会响应**。

---

## 探针 3：未授权拦截（`probe-ungranted.json`）

**授权**：**一个都不要勾选**（安装后直接点「取消」或全不选，保持未授权）

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| 鲸鱼娘气泡 | **不应**出现「未授权测试：不应出现这句话」 |
| 审计日志 | 出现 `call | 说话：... | denied | 未授权能力：让鲸鱼娘说话` |
| 审计日志 | 出现 `call | 打开应用：com.tencent.mm | denied | 未授权能力：打开其他应用` |
| 另有一行 | `probe-ungranted: say=denied: ... openApp=denied: ...` |

**判定**：既没有说话、也没有跳转，且日志两条 denied → 能力闸门有效。

## 实测状态：**待重新验证**（2026-10-18 · App 1.1.47 的结论已作废）

> ⚠️ **2026-10-18 曾在 1.1.47 上跑过一轮，当时记为"三项通过"，但该结论是假阳性，已作废。**
>
> 原因：1.1.29~1.1.47 期间沙箱白名单只放行桥接对象，`say()` / `log()` 等返回 String 时
> Rhino 要为 `java.lang.String` 建包装 → 被 ClassShutter 拒绝 → **动作先执行成功、随后才抛错**，
> 而错误被胶水代码的 `catch(e)` 吞掉。于是：
> - 探针 1 的 `log()` 记录看似成功，其实每次调用都异常中断
> - 探针 2 的脚本**根本没跑到死循环**（`log()` 先抛了），"没有结束行"不代表死循环被中止
> - 探针 3 的 `denied` 记录可信度也需重验
>
> 该缺陷已在 **1.1.47-Extension** 修复（白名单加入 `java.lang.String`，胶水对返回值做 `String(...)` 转换）。

### 重跑步骤（在修复后的版本上）

按本文件上方「探针 1 / 2 / 3」的步骤重新执行，然后把 `Download/whale-plugins.log.txt` 交给代理判读。
**只有重跑结果才能作为"安全机制已生效"的依据。**

### 重跑后的判定标准（避免再次假阳性）

| # | 验证目标 | 判据（必须同时满足） |
|---|---|---|
| 1 | 沙箱不可逃逸 | `Packages`/`java` 为 undefined；`getClass`/`getClassLoader` 抛错；**且 `log()`/`say()` 的返回值为 `ok`**（不是先执行后报错） |
| 2 | 死循环被中止 | 出现「开始」、**无「结束」**；**且**随后其它插件能正常加载执行（线程未卡死）；**且**审计里有中止记录（该记录待补） |
| 3 | 未授权被拦截 | 记录 `denied`、无副作用（无气泡、无跳转） |
| 4 | 敏感确认 | 已授权 `openApp` 时执行会弹确认条；拒绝后审计记 `denied` |

> 说明：探针 2 当前仍有"中止无审计记录"的缺口，需插件方补一条 `error` 记录后再作为完整判据。

## 探针 4：联网能力（`probe-network.json`，1.1.51-Extension 起）

**授权**：勾选「联网请求」+「记录」（`network` 属**敏感能力**，点「始终允许」可免逐次询问）

**操作**：**双击两次**鲸鱼娘。探针按奇偶交替发两种请求，一次只发一个 ——
连发两个会让前一个被后一个顶掉（实测 `denied | 被后来的确认请求顶替`），测不全。

| 第几次双击 | 请求 | 是否弹确认条 |
|---|---|---|
| 1（奇） | `file:///etc/hosts` | **不弹**（协议预检在确认之前就拒了） |
| 2（偶） | `https://www.baidu.com` | 弹 → 点「允许」 |

**预期**：

| 检查项 | 期望结果 |
|---|---|
| 第 1 次 | `call | 网络 GET：file:///etc/hosts | error | 只允许 http/https（收到：file）`，**且没有 `pending`** |
| 第 2 次 | `call | 网络 GET：https://www.baidu.com | ok | status=200 …`，脚本日志拿到 `{"ok":true,"status":200,...}` |
| 审计 URL | **不含 query**（密钥不会进日志） |

**判定**：`file://` 被预检直接拒且不打扰用户、https 拿到 200 信封 → 联网能力可用且边界正确。

> **为什么用 baidu 而不是 GitHub API**：实测 `https://api.github.com/zen` 在该设备上
> `error | connection closed`（网络到达不了），换成国内可达的站点才能验证能力本身，
> 否则测的是网络环境而不是功能。
