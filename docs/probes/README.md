# 插件真机验证探针（probes）

> 目的：把插件系统里**只能用真机确认**的几件事，从"待验证"变成"已验证"。
> 起因：1.1.28/1.1.29 的沙箱与执行上限只有源码/字节码层面的静态验证，
> 审计日志里没有任何 `call` 记录 —— 即插件的实际动作路径从未真正跑过。

## 前提

- App 版本 **1.1.30 或更高**
- 桌宠服务正在运行（设置页的按钮显示「停止桌宠」即表示在跑）
- 日志文件：`Download/whale-plugins.log.txt`（MediaStore 给 text/plain 补了 `.txt`）

安装方式：设置页 → **插件** → **安装** → 把下面某个 JSON 文件内容整段粘贴 → 确定。
安装后会弹出能力授权框。

---

## 探针 1：沙箱边界（`probe-sandbox.json`）

**授权**：勾选「让鲸鱼娘说话」（say）

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| `typeof Packages` | `undefined`（已删除该全局） |
| `typeof java` | `undefined` |
| `__bridge.getClass()` | 抛异常 → 记录 `getClass:blocked` |
| `__bridge.getClass().getClassLoader()` | 抛异常 → 记录 `getClassLoader:blocked` |
| 桌宠表现 | 正常冒一句「沙箱探针已执行，请看审计日志」 |

**判定**：审计日志出现 `probe-sandbox 结果: ... | getClass:blocked | getClassLoader:blocked`
→ 若出现 `getClass=class ...` 或 `getClassLoader=...`（非 blocked），**沙箱无效，必须立即反馈**。

---

## 探针 2：死循环保护（`probe-loop.json`）

**授权**：勾选 say

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| 审计日志 | 出现 `probe-loop 开始（预期被指令上限中止）` |
| 审计日志 | **不出现** `probe-loop 结束（这一行不应出现）` |
| 随后 | 出现一条 `事件处理 | error`（即超时被中止） |
| 桌宠表现 | 双击后鲸鱼娘**仍能正常游动/说话**，UI 不卡 |

**判定**：只要"结束"那行没出现、且桌宠没卡死 → 死循环保护有效。
若桌宠明显卡顿（几秒内无响应）→ 指令上限值（500 万）可能偏大，需下调。

> 注意：这一步会占用插件线程若干秒，属正常现象；期间**其它插件不会响应**。

---

## 探针 3：未授权拦截（`probe-ungranted.json`）

**授权**：**一个都不要勾选**（安装后直接点「取消」或全不选，保持未授权）

**操作**：双击鲸鱼娘

**预期**：
| 检查项 | 期望结果 |
|---|---|
| 鲸鱼娘气泡 | **不应**出现「未授权测试：不应出现这句话」 |
| 审计日志 | 出现 `call | 说话：... | denied | 未授权能力：让鲸鱼娘说话` |
| 审计日志 | 出现 `call | 打开应用：com.tencent.mm | denied | 未授权能力：打开其他应用` |
| 另有一行 | `probe-ungranted: say=denied: ... openApp=denied: ...` |

**判定**：既没有说话、也没有跳转，且日志两条 denied → 能力闸门有效。

## 汇总判定表（跑完后填空）

| # | 验证目标 | 期望 | 实测 | 结论 |
|---|---|---|---|---|
| 1 | 沙箱不可逃逸 | getClass/getClassLoader 均 blocked | | |
| 2 | 死循环被中止 | 无"结束"行 + 桌宠不卡 | | |
| 3 | 未授权被拦截 | 两句 denied + 无副作用 | | |
| 4 | 审计可追溯 | 上述动作全部出现在日志 | | |
| 5 | 敏感操作二次确认 | 用 `openApp` 且已授权时会弹确认条（允许/始终允许/拒绝） | | |

> 第 5 项需要额外一步：给探针 3 授权 `openApp` 后再双击，应弹出悬浮确认条；
> 点「拒绝」→ 日志记 denied；点「始终允许」→ 之后再执行不再询问。

## 跑完把结果告诉代理

把 `whale-plugins.log.txt` 的内容（或上面判定表的实测列）交给代理，即可据此确认：
1. 插件功能是否真的可用
2. 沙箱是否真的关得住
3. 指令上限是否需要调大/调小
