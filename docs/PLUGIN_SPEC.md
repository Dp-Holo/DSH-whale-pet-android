# 宿主能力契约（插件开发规范）

> **维护方：插件宿主侧**（按 AGENTS.md 的目录归属）；能力语义由 App 侧定义，双方共同遵守。
> 本文件是插件与 App 之间的**唯一接口契约**。插件开发只依据本文件，不需要读 Kotlin 源码。
> 契约变更流程见文末 §9，行为变更记录见 §10。

- **契约版本**：`apiVersion = 2`（对应 App `1.1.47`；`apiVersion = 1` 为初始契约，App 1.1.30）
- 插件文件：`{"id","name","version","enabled","capabilities"}` + **`script` 或 `rules`（二选一）**，
  也可再加 `scriptFile` 用外部 `.js`（见 §1.2）
- 脚本语言：JavaScript（Rhino 引擎，ES5 语法为主；`JSON`、`Array`、`String`、`Math` 可用）

---

## 1. 插件文件格式

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": 1,
  "enabled": true,
  "capabilities": ["say", "notify"],
  "script": "on('doubleTap', function (ctx) { say('你好'); });"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一标识，**强制校验**：字母或数字开头，其后只允许字母、数字、`.`、`_`、`-`，最长 64；**不允许 `/` 与中文**（id 会被拼成文件名落盘，不合规直接拒绝安装）。**授权按 id 记录**，改名等于新插件 |
| `name` | ✅ | 界面显示名 |
| `version` | 建议 | 插件自身版本号（整数），仅作标记 |
| `enabled` | 建议 | 默认 true |
| `capabilities` | ✅ | 需要的能力（见 §3）。**规则里用到的能力会自动补齐**，但仍建议显式声明 |
| `script` | 二选一 | JS 源码（单行字符串，内部用单引号避免转义）。**与 `rules` 二选一** |
| `rules` | 二选一 | 规则型：事件 → 动作数组，格式见 §1.1。**与 `script` 二选一** |
| `scriptFile` | 可选 | 外部脚本**文件名**（元数据/展示用，**不是路径**）。写了它但未绑定文件时插件不执行，界面会提示"未选择脚本文件"。详见 §1.2 |

**脚本来源优先级**（三种形态可共存，按此顺序取第一份可用的）：

```
已绑定的脚本文件（用户经系统文件选择器选定且可读） > 内联 script > rules（规则型）
```

> 文件名失效（被删/失去授权/超限）时自动回退到内联 `script`；两者都没有才判定为"未加载"并写审计。

### 1.2 外部脚本文件（`scriptFile`）

复杂的脚本内联进 JSON 只能写成 `\n` 转义的一长串。改用外部 `.js` 文件后可以正常换行、写注释。

**流程**（全部由 App 界面完成，插件作者只需声明文件名）：

1. JSON 里写 `"scriptFile": "my-plugin.js"`（只是展示名字，不参与路径解析）
2. 安装后 App 自动弹出**系统文件选择器**，用户选中实际的 `.js`
3. App 用 `takePersistableUriPermission` 持久保存读取授权，之后从该 URI 读内容执行
4. 之后可在插件菜单里「选择 / 重新选择脚本文件」更换

**限制**：

| 项 | 限制 |
|---|---|
| 大小 | **256KB**，超出直接拒绝并写审计 |
| 编码 | UTF-8 |
| 访问范围 | 只能读用户**明确选中**的那一个文件；不会扫描目录 |
| 沙箱 | 与内联脚本**完全一致**（ClassShutter + 指令上限），来源不同不改变执行路径 |

**生效时机**：绑定或更换文件会立刻重载。**直接改 `.js` 文件内容不会自动重载**——
重新点一次「选择 / 重新选择脚本文件」，或重启桌宠即可。

**审计**：绑定时写 `manage | 绑定脚本文件：<文件名> | ok`；读取失败写
`load | 脚本文件不可用 | error | <原因>`。

### 1.1 规则型插件格式（`rules`）

规则型插件不写 JS，只声明"哪个事件发生时做哪些动作"：

```json
{
  "id": "balance-guard",
  "name": "余额守卫",
  "capabilities": ["say", "notify"],
  "rules": [
    {
      "when": { "event": "balanceDecreased" },
      "then": [
        { "action": "say", "text": "又少了一点…" },
        { "action": "notify", "title": "余额不足", "text": "记得充值" }
      ],
      "cooldownMs": 60000
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `when.event` | ✅ | 事件名，取值见 §2（与脚本型的 `on(...)` 同一套事件） |
| `then[].action` | ✅ | 动作名，取值见 §3（`say` / `notify` / `vibrate` / `openUrl` / `openApp` / `shizuku` / `log`） |
| `then[].text` / `title` / `url` / `pkg` / `ms` / `args` | 视动作 | 与 §3 各 API 的参数一一对应 |
| `cooldownMs` | 可选 | 同一规则两次触发的最小间隔（毫秒） |

**节流有两层**：
1. `cooldownMs`：你自己声明的间隔；
2. **1 秒硬下限**：所有规则动作都受它约束，即使 `cooldownMs` 写 0 也是 1 秒一次——
   防止把 `notify` 绑到 `tap` 上连点轰炸通知栏。

> 规则里用到的能力会自动补进 `capabilities`，但**仍建议显式声明**，否则授权框里看不到来源。

## 2. 事件（用 `on(事件名, 处理函数)` 订阅）

处理函数收到一个对象 `ctx`，字段如下：

| 事件名 | 触发时机 | `ctx` 字段 |
|---|---|---|
| `appStart` | 桌宠服务启动后约 1.5 秒 | 无 |
| `balanceDecreased` | 余额**减少**时（App 每 3 秒静默查询） | `value`(Number 新余额)、`prev`(Number 旧余额) |
| `batteryLow` | **刚**进入低电量（≤20% 且未充电） | `level`(Number 百分比) |
| `screenOff` / `screenOn` | 息屏 / 亮屏 | 无 |
| `tap` | 单击鲸鱼娘 | 无 |
| `doubleTap` | 双击鲸鱼娘 | 无 |

**注意**
- 事件是"通知式"的：错过不补发，不做队列。
- `ctx` 只有上表字段，**不要依赖其它字段**。
- 同一个事件可以注册多个处理函数；异常会被隔离（写审计日志，不影响其它插件）。
- **暂不支持定时事件**：只有上表这些 App 侧事件，没有"每 N 分钟触发一次"。
  旧版本解析过一个 `intervalMs` 字段但从未读取，容易让人误以为定时可用，已在 1.1.40 移除。

> 规则型插件（用 `rules` 而非 `script`）的字段与节流说明见 **§1.1**。

示例：
```js
on('balanceDecreased', function (ctx) {
  var used = ctx.prev - ctx.value;
  say('又消耗了 ' + used.toFixed(2) + ' 元');
});
```

## 3. 动作 API（能力）

| API | 能力名 | 参数 | 敏感 | 返回 |
|---|---|---|---|---|
| `say(text)` | `say` | 文本 | 否 | `ok` |
| `notify(title, text)` | `notify` | 标题、正文 | 否 | `ok` |
| `vibrate(ms)` | `vibrate` | 毫秒（1~5000，默认 300） | 否 | `ok` |
| `openUrl(url)` | `openUrl` | 完整 URL（需带 scheme） | ✅ | `ok` / `error: 无法打开` |
| `openApp(pkg)` | `openApp` | 应用包名 | ✅ | `ok` / `error: 应用不存在` |
| `shizuku(...args)` | `shizuku` | 白名单命令参数 | ✅ | 命令输出诊断串（见 §5） |
| `log(text)` | —（无需能力） | 文本 | 否 | `ok` |

**返回值语义**（脚本可据此分支）：
| 返回 | 含义 |
|---|---|
| `ok` | 已执行 |
| `denied: 未授权 …` | 该能力未被用户授权 |
| `pending: 等待用户确认` | 敏感操作已弹出确认条，用户尚未选择；**确认通过后才会真正执行** |
| `error: …` | 执行失败（参数错误、系统拒绝等） |

**重要**：敏感能力是**异步确认**的 —— `openApp()` 返回 `pending` 不代表已打开，真正打开发生在用户点「允许」之后。

**返回值类型**：上表所有能力的返回值都是**普通 JS 字符串**，可以直接比较：
`if (say('hi') === 'ok') { … }`。

## 4. 用户侧的授权与确认（插件作者必须理解）

1. **安装时**：App 弹出能力授权框，用户逐项勾选；未勾选的能力调用**一律被拒**。
   **覆盖安装（同一个 `id` 重装）会清空该插件此前的全部授权**（含"始终允许"），必须重新勾选——
   否则一份同 id 的新脚本就能直接继承旧脚本的能力，等于绕过确认。
2. **敏感能力**（`openUrl`/`openApp`/`shizuku`）：即使已授权，**每次执行**也会弹悬浮确认条：
   - 「允许」→ 本次执行
   - 「始终允许」→ 该插件的该能力以后不再询问
   - 「拒绝」或 **15 秒未操作** → 视为拒绝
   - **点「允许」后还会再复查一次授权**：这 15 秒里用户若已在管理页撤销授权、
     停用或删除插件，动作**不会执行**，审计记为 `denied | 授权已变更：…`
3. **全程审计**：每次调用（含被拒、失败）写入 `Download/whale-plugins.log.txt`。
   审计记录的是**真实原因**：`用户拒绝` / `15 秒内未选择，视为拒绝` /
   `被后来的确认请求顶替，未执行` / `桌宠服务已停止，未执行` / `悬浮窗不可用，无法确认`。

> 因此插件**不要设计成"依赖静默执行"**：敏感动作可能被拒绝，代码要考虑返回值并优雅降级。

## 5. `shizuku` 的可用范围（受限）

插件只能执行 **App 白名单内的命令**，且目标包名必须是本应用：

| 命令 | 用途 |
|---|---|
| `shizuku('appops','set','<pkg>','SYSTEM_ALERT_WINDOW','allow')` | 悬浮窗授权 |
| `shizuku('pm','grant','<pkg>','android.permission.POST_NOTIFICATIONS')` | 通知授权 |
| `shizuku('dumpsys','deviceidle','whitelist','+<pkg>')` | 电池优化白名单 |

- `<pkg>` 只能是 `com.dsha.whalepet` 或 `com.dsha.whalepet.debug`（**精确匹配**）
- 其它命令一律被拒（返回"拒绝执行：命令不在白名单内"）
- 白名单扩展需 App 侧改代码（见 §9），**插件方无法自行扩展**

## 6. 沙箱边界（能做什么 / 不能做什么）

**可用**：JS 标准对象（`Array`/`String`/`Math`/`JSON`）、上表 API、`on`。

**不可用（会抛错或被拒绝）**：
- ❌ 任何 Java 类：`Packages`、`java`、`javax`、`org`、`com`… 全局已删除
- ❌ `__bridge.getClass()` / `getClassLoader()` 等反射逃逸（白名单只放行 `__bridge` 与
  `java.lang.String`；反射的必经节点 `java.lang.Class` / `ClassLoader` 一律被拒）
- ❌ 文件读写、网络请求（未提供对应 API）
- ❌ 其它插件的作用域（每个插件独立作用域，互不可见）

**执行限制**：单次执行最多 **500 万条指令**，超时会被强制中止（抛错、写审计），脚本的 `try/catch` 拦不住。
- 结论：**不要写死循环或重负载循环**；长任务应拆成多次事件触发。
- 插件运行在独立后台线程：插件卡住**不会**影响桌宠动画与 UI，但会阻塞其它插件的执行。

## 7. 审计日志格式

文件：`Download/whale-plugins.log.txt`（1MB 自动清除历史，同名变体自动收敛）

```
MM-dd HH:mm:ss | 插件id | 事件或动作类别 | 动作描述 | 结果 | 详情
```

结果取值：`ok` / `denied` / `error`；另有 `grant`（授权）、`revoke`（撤销）、
`load`（加载）、`manage`（启用 / 停用 / 删除，会写明动作）。

> `shizuku` 的结果按真实情况记：被白名单拒绝记 `denied`，通道不可用或执行异常记 `error`
> （此前一律写 `ok`，安全拦截在日志里看不出来）。

> 插件可控的字段（`id`、动作描述、`log()` 正文）里的换行会被转义成字面量 `\n`，
> 保证**一次调用只占一行**。别试图用它伪造日志——转义后只会留下痕迹。

示例：
```
10-11 23:16:50 | sample-starter | grant | 授权能力：say | ok
10-11 23:22:02 | sample-starter | load | 脚本已加载 | ok
10-11 23:25:10 | probe-ungranted | call | 打开应用：com.tencent.mm | denied | 未授权能力：打开其他应用
```

调试建议：把关键分支用 `log()` 打点，用户跑一次后你就能从日志看到实际路径。

## 8. 开发与验证建议

1. 先写最小插件（`on('doubleTap', …)` + `say`），确认链路通
2. 用 `docs/probes/` 里的三个探针确认沙箱/超时/未授权拦截
3. 复杂逻辑用 `log()` 打点，别靠猜
4. 插件正文建议保持在**几十行以内**；重逻辑说明事件选错了

## 9. 契约变更流程

新增/修改事件或能力，必须由 **App 侧**执行：

1. `PluginCaps` 登记能力（含是否敏感）
2. `PluginManager.handleCall` 实现授权 + 确认 + 审计
3. `PluginEngine` 胶水暴露对应函数，**并同步 ClassShutter 白名单**（若涉及新的 Java 类型）
4. 更新本文件与 `apiVersion`，在 App 版本说明里注明
5. 现有插件**向后兼容**：不删除已有事件/能力名，只增不改

> 插件侧有需求 → 提给 App 侧 → App 侧实现后更新本文档 → 插件侧再使用。**不要假设未列入本文件的能力可用。**

## 10. 行为变更记录

契约版本 `apiVersion = 2` 对应 App `1.1.47`。以下是 1.1.31 起**影响插件行为**的变化（§9 要求的登记）：

| App 版本 | 变化 | 对插件的影响 |
|---|---|---|
| 1.1.31 | 授权框空选择不再写入授权 | 无（UI 行为） |
| 1.1.32 | Shizuku 白名单修正（`pm grant` 只有 4 个参数）；包名改**精确匹配** | 通知授权类命令这才真正可用 |
| 1.1.39 | `id` 强制字符集；**覆盖安装清空该插件全部授权**；审计转义换行 | 插件改名等于新插件；重装必须重新授权 |
| 1.1.40 | 移除从未生效的 `intervalMs` | 该字段被忽略；**定时事件不支持** |
| 1.1.42 | 授权变更后点「允许」会复查；确认结束原因细分；`shizuku` 结果按真实情况记；规则动作 1 秒下限；启停/删除写审计 | 敏感动作可能因"授权已变更"被拒 |
| 1.1.47 | 授权框改为**全量替换**（取消勾选真正生效）；被撤销能力的"始终允许"一并清除；处理函数抛异常与非正常中止都会写审计 | 取消勾选后对应能力立刻失效；调试时能在日志看到报错原因 |
| 1.1.47-Extension | 修正沙箱白名单：放行 `java.lang.String`；能力返回值转为普通 JS 字符串 | 1.1.29 起"能力生效但脚本随即被中断"的问题修复；`say(...) === 'ok'` 这类比较现在成立 |
| 1.1.51-Extension | 支持外部脚本文件 `scriptFile`（SAF 选择 + 持久授权，上限 256KB）；优先级 文件 > 内联 > 规则 | 复杂脚本不必再挤成一行；文件失效时有审计与提示，并能回退内联脚本 |
