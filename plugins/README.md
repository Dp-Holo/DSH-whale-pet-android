# 插件目录（插件侧负责）

> 本目录归**插件内容**维护方（代理 B）使用；宿主能力契约见 [`../docs/PLUGIN_SPEC.md`](../docs/PLUGIN_SPEC.md)。
> App 本体（宿主实现）由代理 A 维护。

## 放什么

- 本目录放**插件源文件**：一个插件一个 `<id>.json`
- `examples/` 放示例插件（面向新用户，保持"开箱可用、无需敏感能力"）
- 可另建 `tutorials/` 放图文教程、`changelog.md` 记录插件变更

## 约定

| 约定 | 说明 |
|---|---|
| 文件名 | `<插件id>.json`，与 JSON 内 `id` 一致（`examples/` 例外：用 `序号-中文名.json` 便于阅读，真正的 id 以 JSON 内为准） |
| `id` 字符集 | **强制校验**：字母或数字开头，其后只允许字母、数字、`.`、`_`、`-`，最长 64；**不允许 `/` 与中文**。因为 id 会被拼成文件名落盘，不合法会直接拒绝安装（1.1.39 起） |
| 能力 | 优先只用 `say` / `notify` / `vibrate`；**敏感能力（openUrl/openApp/shizuku）要说明用途**，并保证被拒绝时能优雅降级 |
| 事件选择 | `screenOff` 触发时屏幕已熄灭，`say` 的气泡**用户看不到**；要提示请用 `notify`，但别每次锁屏都弹（会很烦） |
| 依赖 | 只使用 `docs/PLUGIN_SPEC.md` 中列出的 API；**不得假设未列入的能力** |
| 外部脚本 | 脚本可放外部 `.js`：JSON 只写 `"scriptFile": "文件名"`（**只是展示用元数据，不是路径**），用户在 App 里通过系统文件选择器绑定后才会执行。上限 256KB。本目录的 `examples/hello-script.js` + `5-外部脚本示例.json` 是一对完整示例 |
| 兼容 | 新插件应注明所需契约版本（`apiVersion`）与最低 App 版本 |
| 安全 | 不得尝试反射逃逸、越权调用、绕过能力确认；违反者按安全事件处理 |

## 怎么交付给用户

插件最终要装进 App 的私有目录，路径只有两条（都需用户操作）：

1. **从文件导入**（1.1.51-Extension 起）：设置 → 插件 → 安装 → 「从文件导入插件」→ 系统文件选择器选中 `<id>.json`
2. **App 内粘贴**：设置 → 插件 → 安装 → 「粘贴插件 JSON」→ 粘贴 JSON 全文（最通用）

> 两条路走的是**同一套安装流程**（id 校验、覆盖安装清授权、`scriptFile` 选文件、能力授权），
> 不存在"导入的插件少一道关"。
> 也就是说：仓库里的插件**不会自动进入用户设备**，仍需用户自己选择文件或粘贴。

## 与 App 侧的接口变更

需要新的**事件**或**动作能力**时，按 [`../docs/PLUGIN_SPEC.md`](../docs/PLUGIN_SPEC.md) §9「契约变更流程」提需求
（说明：要什么能力、什么场景、是否敏感），由 App 侧实现并更新契约后再使用。

**不要**直接改 App 代码目录（那是宿主实现，改动会破坏安全模型）。
